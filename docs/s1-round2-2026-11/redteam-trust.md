Lens: parents on shared networks, what a crawler sees, what Google may flag. No code edited. Severity: H blocks ship, M fix in slice, L note.

## S3 indexing

1. H. R3.2/R3.3, template line 6 hardcodes `<meta name="robots" content="noindex">` and both routes send `x-robots-tag: noindex`. Removing only the meta leaves the header; header wins, page stays deindexed and the test passes on markup. Scenario: ship, Search Console says "noindex detected". Change: remove the header in /join only, add a per-route head SEO block var (robots, canonical, description, JSON-LD) replacing line 6, and add a test that /join response has neither signal while /join/b, /jersey, /signup, /season1 have both.
2. H. R3.2, indexability is not conditioned on mode. A host that is not live (deploy preview, branch deploy, a test-mode build on the real host) would serve an indexable page with the yellow "Test mode. No real charges." bar and a canonical pointing at prod. Change: robots is `index` only when `isLiveHost(host)` and mode is `live`; every other case keeps noindex header and meta. Test the matrix (host x mode x open).
3. H. Closed state after closeAt. `open` is computed per request, so the indexed page becomes "Signups are paused. Text our founder." while title, description, JSON-LD Offer and FAQ still say open and $100. Google snapshots a paused page under a sales snippet, and Offer then misstates availability. Change: JSON-LD built from the same `open` flag (closed: drop Offer or `availability` Discontinued/`validThrough`, title and description closed variants). Decide now: stay indexed when closed (recommended, no deindex churn) with honest copy.
4. M. Offer facts. Price is a first-month $100-class deposit then monthly, Offer needs `price`, `priceCurrency`, `url`, `availability`, `validFrom`/`validThrough` from `OFFER.openAt/closeAt`; "Course provider" must be the existing `ORG_ID` node, not a new Organization. A Course with `hasCourseInstance` needs real dates (mid Jan to May 2027, `courseMode` Online, `courseWorkload`). Do not claim the $60 saving as a second price, Google flags price mismatch with visible text. Every number comes from offer.ts so schema cannot drift from the page. Free jersey/friend-free-season must not go in Offer (conditional, ends at cutoff).
5. M. FAQPage. Google restricts FAQ rich results to gov and health sites, so expect no rich result; markup stays valid but must equal visible text exactly. Template answers use `{{vars}}`, Jamie-approved canon wording must be the same string on page and in JSON-LD (single source, rendered once). Page FAQ text currently differs from canon plans ("Every coach is background-checked", "you get every dollar back", "drop in on any practice"): each is a public safety/refund claim that becomes crawlable and citable by AI answers. Verify each against terms before indexing.
6. M. Duplicate content with /join/b. Identical template, b is noindex and has no canonical. Change: give b `canonical` to /season1/join with noindex omitted is contradictory, so keep b noindex only, no canonical (Google ignores canonical on noindex). Accept. But /karlin 307s to /join/b: confirm it is not in sitemap or llms.txt.
7. M. Query variants. Any `?utm_*`, `fbclid`, `gclid`, `?src=`, `?s1qa=` yields a distinct URL with identical content (src also rewrites SIGNUP hrefs). Absolute canonical to the bare path handles it; the canonical must be a constant, never built from the request URL or Host (www vs apex, preview host). Add test: `?src=karlin&utm_source=x` canonical equals bare.
8. M. Crawlers fire tags. Googlebot's renderer runs JS: GA4 page_view, Pixel PageView + ViewContent (`join.viewContent`), Clarity all load on live host. Inflates ViewContent and Meta audiences, skews GA. Change: server-side skip all tags when UA matches known bots (Googlebot, bingbot, facebookexternalhit, GPTBot, etc.), or accept and note. Cheap: one regex in `renderTags`.
9. L. Private params on an indexed page: only the 8 LC keys, `src`, `s1qa` survive `renderUrlAllow`, but GA `page_location` carries them. No codes or emails ride /join (referral codes live in /crew and checkout). Add a test that `/season1/join?code=X&email=a@b.c` strips both before tags run.
10. L. `cache-control: private, no-store` on an indexable page is legal but hurts crawl and speed; it exists because tags/mode are per-request. Keep for now; do not add `s-maxage` unless the Host-dependent tag block is varied by Host. `x-frame-options` unaffected. Netlify previews also add their own noindex header: fine.

## S2 route guards

12. H. R2.3 step lock and reload. `eventId` and `savedEmail` live only in page memory (landing.html ~1426). A parent who signs up, reloads (or returns via back, or the popup flow re-mounts) then taps Text Karlin sends a new/no eventId: server returns `200 {ok:true}`, page shows the "done" state, request silently dropped. This is a real parent who gave a phone number and was told Karlin will text. Change: persist `{emailKey, eventId}` in sessionStorage/localStorage on success (never the phone), reuse on steps. And the lock must not be silent for text-karlin: on no match return a distinct non-leaking `{ok:false,error:"Please sign up again"}`? That reveals a claim miss only to someone who already has the email, acceptable; or accept text-karlin on email match alone within 24 h. Test: reload then text-karlin succeeds.
13. M. Same silent success for `games` (hero=games, fire-and-forget) and `age`: lost data with no signal. Add a counter/log (hashed) for dropped steps so Jamie sees the loss rate after launch.
14. M. 24 h window: parent signs up Monday night, returns Wednesday from the email link, hits Text Karlin: dropped. Prefer 7 days for steps, or extend claim TTL on every step.
15. M. R2.1 quiet path. More than 5/hour per IP saves but sends no CAPI/browser Lead. A school or office NAT after an ad burst reaches 5 fast; those families are real and become uncounted conversions (attribution loss, not user harm). Raise to 10, or key on IP + UA hash, and log quiet count per hour so tuning is visible. User still sees the normal confirmation, good; keep copy identical.
16. M. R2.1 429 copy. "Too many sign-ups from this connection. Text our founder at ..." tells a real parent they did something wrong and the number is shown to bots too. Change: "We could not save this one from here. Text our founder at +1... and we will add you by hand." The landing must render `error` for a 429 (currently throws to its generic "didn't go through" path: check). Never write the email to log or Klaviyo on 429 (as spec), and the page must not retry-loop on 429.
17. M. IP header trust. `x-nf-client-connection-ip` is set by Netlify; on non-Netlify or local, falling back to first `x-forwarded-for` is client-spoofable, so an attacker can rotate XFF to dodge the limit or poison a victim's bucket to push them into quiet/429. Use XFF only when the nf header is absent AND not live host; hash with a per-deploy salt so the key is not a reversible IPv4 hash (32-bit space brute forces) and TTL it to the window. Retention of `s1_rate_limits` should be bounded.
18. L. Fail-open 800 ms timeout adds up to 800 ms to p95 on DB slowness; run in parallel with classifySignup.
19. L. R2.4 response `quiet:true` leaks to a scripter that they are throttled; acceptable. `repeat` already leaks email existence to anyone: confirm it is the existing behavior and not new.
