# Builder notes (Relay, Chronos, Atlas) for the beta restart link

Built on `build/beta-restart-link` from the frozen spec. Written for the QA agent: what was interpreted, what was not proven in a real browser.

## Interpretations of the spec

1. **Redirect route imports.** The spec says the route has "no imports beyond the cookie names and shape check". Those live in `lib/season1/betaRestartCookies.ts`, a file with no imports of its own; `betaRestart.ts` re-exports it. A rollback that keeps `app/season1/beta/r/[token]/route.ts` must keep that one file too. A test asserts both facts.
2. **`restartToken` returns `string | null`.** A non-uuid id (or an uppercase or dashless one) returns null and never throws. It does throw when no secret is configured (`refSecret()`), which is why both callers wrap it: the progress save in its own try/catch, the restore route answering 503.
3. **`verifyRestartToken(token, rowId, sessionId)`** takes the row id as well, because the route reads the row by the id in the token and then checks the signature against that row's session. It also rejects encodings that decode to the same bytes (stray low bits) so there is one token per row and session.
4. **Expiry before done.** The restore select computes `fresh` in SQL (`updated_at > now() - make_interval(days => 14)`). A finished row older than 14 days reads `none`, not `done`, following the order of the spec's list.
5. **429.** The spec does not say what an over-limit answer is. It is `429 {ok:false}`, cookies kept, no-store. The script treats any non-200 as "do nothing, keep the flag" and retries only 503 and network errors. The shared no-IP bucket `s1br:noip` has a limit of 600 an hour (one address gets 60); the spec gave no number.
6. **Client IP helper** is a copy of `/api/season-one`'s (that file is untouched), local to the restore route.
7. **Done and none are guarded like the panel.** All three outcomes apply only while the parent is still on the first screen with nothing typed (M4). A `done` that arrives after typing does nothing; the flag is still deleted after the 200.
8. **Panel layout.** Headline is a `p.sub` (not an `h2`, so `show()` never focuses it and a second large heading does not stack on "Get started"). Buttons are in the page's `.acts` row: "Start fresh" (`btn back`) on the left, "Pick up where I left off" (`btn`) on the right, the page's own order for back and primary. A few inline styles give the panel a bottom rule and spacing. The panel is removed when the parent types or leaves the first screen, so it can never reappear on a Back.
9. **Failed confirm.** If the confirm call fails after its retry the buttons are simply re-enabled; no fourth string was added. A confirm that comes back `done` or `none` shows the end screen or the dead-link line.
10. **Start fresh** also moves focus to the email field (one focus move on the tap).
11. **`step` in the `resume` answer** (1 to 3) is returned as specified but the script does not use it; the walk goes by the saved `stage`.
12. **Zone table.** Built by offset: Regina and Phoenix are Central and Mountain (no DST, winter offset), Whitehorse, Dawson and Yukon read Mountain (UTC-7 all year since 2020), Adak and the Aleutian aliases read Hawaii, Atlantic, Newfoundland, Puerto Rico and the Virgin Islands read Other. Rule in the script: any other `America/`, `US/`, `Canada/` zone reads Other; anything else is left as the page set it (the page already sets Other for non-America zones). The table has 89 keys.
13. **Link base.** `restartLinkBase()` reads `S1_DEPLOY_CONTEXT || CONTEXT` via the repo's `deployContext()`, as the rest of the code does. `CONTEXT` is documented as unreliable in the function runtime (see `lib/season1/mode.ts`); if Production does not expose either, links are not written and only the plain fallback exists. Worth checking on the preview before release. `DEPLOY_PRIME_URL` reaching the function runtime is also unverified.
14. **Progress property only with a row.** `beta_restart_link` is added when the save returned an unfinished row. With no database (no row) it is absent.
15. **Next is 16.4.3** in this repo (the brief said 15). The route handler signature uses `params: Promise<...>` like `app/crew/[code]/route.ts`.
16. **Tests live under `lib/season1/__tests__/`** because `scripts/run-tests.mjs` only collects `lib/**/__tests__`; the route tests import the routes from `app/`.

## "done" state: what the page's own `show(4)` does, and what the script copies

`show(i)` in `start.html` (read only) does, for i = 4: `cur=4`; every `[data-step]` section hidden except index 4; for each of the three `#dots li`: `on` toggled off (`n===3` never true), `was` added (`i===4`), `aria-current` removed; focus on the section's `h2` (`preventScroll`); scroll `#dots` into view (smooth unless reduced motion). The script does exactly those DOM changes (`finish()`), plus: removes the panel, clears the saved run, marks the run done, fires `beta_wizard_resume {step:"done", via:"link"}`.

Not copied, because it lives in the page's closure: the page's own `cur` stays 0. Nothing on the end screen uses it (no Continue, Back or submit button is in the last section, and `doneh` and `pc2` keep their markup defaults: "Got it." and an empty, hidden card). If Aaron later adds a control to the end screen that calls `show(cur-1)`, this would need a look.

## What was checked, and how

- `npm test`: see `evidence/builder/npm-test.txt` (717 tests in lib: 716 pass, 0 fail, 1 skipped; plus 5 in `scripts/field-vitals`, all pass). `npx tsc --noEmit`: clean (`tsc.txt`). `npm run build`: passes, run in a copy (see below), `/season1/beta/r/[token]` and `/api/season1-beta/restore` are both listed as dynamic, and the built `/season1/beta/start` body carries the script (`build.log`).
- Environment limits: the machine's `/sessions` disk was full (about 30 MB free), so `node_modules` is in `/tmp/ekuzo-nm` and symlinked into the repo (git ignores it), and the build ran in a copy of the working tree at `/tmp/ekuzo-build` (Turbopack refuses a `node_modules` symlinked from outside the root). The build needed two placeholder env values (`STRIPE_SECRET_KEY`, `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`), which the repo's other routes require at page-data time; nothing from this feature needs them.
- **Browser behaviour was exercised in jsdom, not a real browser.** `evidence/builder/jsdom-check.mjs` loads the real `start.html` plus the generated script (`/tmp/jsd/script.js` is `BETA_PROGRESS_JS` written to a file; jsdom is installed in `/tmp/jsd`, not added to the repo) with stubbed fetch, cookies and `gtag`, and prints `jsdom-check.txt` (all ok). It covers: 20 zone cases, the panel, the tap and the walk to the player card with the same session, no progress post and only the new step counted afterward, GA4 shapes, Start fresh, typing before the response (no panel), done (DOM state, no posts), none line, saved run wins (clear only), tzSet restore, 503 then 200 retry, two failures keep the flag, a preview host still calls the endpoint, no flag means no call (M8). jsdom needs two shims (named form properties such as `f.tz`, and `scrollIntoView`/`matchMedia`); real browsers have them.
- **Not verified in a real browser:** cookie behaviour of `Secure` and `Path=/season1/beta` across a real 302 (the flag cookie path versus the page at `/season1/beta/start`), Safari and iOS Mail handling of the link, real focus and scroll feel, the panel's look next to Aaron's CSS (it uses `sub`, `lede`, `acts`, `btn`, `btn back` only), the 1.5 s retry on a real flaky network, and `DEPLOY_PRIME_URL` / `CONTEXT` in the function runtime (item 13).
- No server-side environment value, migration or dependency was added. `app/api/season-one/route.ts`, `start.html`, `launch.html`, `beta.html`, `middleware.ts`, everything else under `app/season1` outside `beta/r/`, and the Stripe webhook show zero diff against `fe494e2`.
