# Red team: users, trust and privacy

Reviewer lens: the family's side. Read-only on code. Reviewed: 01-requirements.md, 02-frozen-spec.md, start.html, betaProgressScript.ts, betaWizard.ts, tags.ts, start/route.ts, middleware.ts, season-one-tracking.md (beta section), defect log (D1 to D4, D10, D11 not re-raised).

Two facts from the code that several rows rest on:
- The time zone select sits on the last form screen (`data-step="2"`, availability). Progress posts go out only when a parent leaves screens 0 to 2 (email, expectations, player card), so at every resume point the parent has never seen the select. A saved `timeZone` is always an unconfirmed guess.
- `/season1/beta/start` is `force-static` with `renderStaticTags("landing")` and no `{{URL_ALLOW}}`, so GA4 `page_location` is the full address including any query string, and Pixel and Clarity read the same address.

## Classes checked and found closed

- Token in an address that loads a vendor tag: the token appears only on `/r/<token>`, which is a 302 with no HTML. `/start` is reached with no token in the Location, so GA4, Pixel and Clarity never see it. The `Referrer-Policy: no-referrer` on the redirect response applies to the redirected request, so the final request carries no referrer either (side effect: link arrivals show as direct in GA4, which affects reporting only).
- Referrer from `/start` to Google Fonts and tag hosts: origin only, no path, no token.
- Cross-site POST to restore: the Origin guard plus `SameSite=Lax` means no cross-site request carries the cookie, and a cross-site page cannot read the response. A forged or guessed token: 256 bit HMAC, constant-time compare, row id and session bound. Rate limit failing open is fine for that reason.
- Finished family: `done` returns no name, age, answer or email (M3), the end card renders empty (`.pc:empty` is hidden) and the headline is generic. The yes/no is reachable only with a valid token.
- Safari ITP and in-app cookie loss on the redirect: the cookies are first party, set by ekuzo.gg on a same-site redirect, so ITP caps and third-party storage blocking do not apply; same-origin POST sends them. Failure remains only where a different browser or profile opens the page (B7).
- Mail prefetch (Apple Mail Privacy Protection loads images only), link-preview bots that do not run JS (the 302 yields the public start page, nothing is consumed), Klaviyo bot-click filtering: no state change and no cookie consumed on a plain GET.
- Page HTML is static and CDN cached; no per-family HTML is served, so nothing about a family can be cached or shared by the CDN.
- Clarity: recording prefilled fields is allowed by the brief; noted only that the rendered player card text (`#pc`, `#pc2`) is page text, not an input, and Clarity's default masking does not hide page text. Same as the existing same-device restore.
- Stranger with only an email: D1 and D2 already accept a stranger posting progress for an address. New consequence worth feeding into the flow requirement, not re-raised: a stranger's new-session post kills the parent's emailed link (L5) and replaces the saved answers, so the parent lands on B7's blank screen. Covered by the B7 copy.
- Klaviyo property `beta_restart_link` readable by the team: the team already holds the answers in the same profile, so no new audience. Do not add the property to any list, audience sync or campaign personalisation.
