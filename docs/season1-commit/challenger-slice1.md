## Notes

- Strongest suggestion: row 3. As drafted, the claim-then-steps flow over HTTP can orphan a paid order. That is a correctness fix that costs about 20 lines.
- Cut: row 1, ECE deferred to slice 4. Row 4 (the rate-limit table) is a second cut that is clearly cheaper and removes no requirement, so it can be adopted tonight.
- Add a partial unique index on `s1_codes(family_id) WHERE type='family'`, so two concurrent orders from one family (a sibling added later) can't mint two family codes.
- PM scope R1 still shows the 9-digit display `4827 1937 6`. The spec correctly follows the brief override (8 digits, `4827 1937`). Copy and tests should use the override.
- Unverified: Neon WebSocket behaviour inside Netlify's Next.js runtime. Prove it with one transaction in the slice 1 skeleton push. If it fails, use the `fulfilled_at` variant in row 3.
