## Checked and found clean

- **Secrets in the tracked diff and the untracked scripts.** Pattern scan over 116 non-image files for `sk_/rk_` live or test keys, `whsec_`, Postgres URLs with credentials, Neon `npg_` passwords, Meta `EAA` tokens, Discord webhook URLs, AWS/Slack/GitHub tokens and private keys: no hits. One `pk_test_` in `docs/season1-commit/evidence/sentry-s1/j1-result.json` (publishable, test mode, public by design). No PaymentIntent client secrets in evidence files (placeholders `<cs>` only); no `s1_order` token values. Emails in evidence are `team+s1test-…@ekuzo.gg` or obvious test addresses. `.env.local` is gitignored and untracked; `.env.local.example` holds no key-shaped values. The Neon test endpoint id in `mode.ts` and tests is a host label, not a credential.
- **SQL injection.** Every query in `lib/season1/*.ts` and `scripts/s1-*.mjs` uses `$n` parameters. The only interpolations are constants (`PAID`, `MAX_ATTEMPTS`, `MARK_STALE_TEST_AGE_MIN`, `FULFIL_COLS`, `REFERRAL_COLS`, `ORDER_VIEW_SELECT`), a static conditional clause in `outbox.ts:219`, and a static column toggle in `s1-refund.mjs:40`. The migration runner executes repo files only.
- **HTML escaping.** `/crew/<code>`: the name and code line go through `esc()` (`&<>"'`); all other vars are offer constants. `/season1/join`: every var escaped except `CLOSED_BLOCK`, which is built from constants with the SMS number escaped; `src` is whitelisted. `/season1/join/welcome`: kid names, order ref, link and code are escaped; `data-kid`/`data-link` attributes are escaped. `/season1/terms`: constants only. Signup page: config injected as JSON with `<`, `>`, `&`, U+2028/2029 escaped for script context; the invite name is rendered via `textContent` and the client `esc()` in the summary; kid names in the summary use `esc()`; `duplicate_kid` errors use `createTextNode`.
- **Cookie flags.** `s1_order`: `HttpOnly; Secure; SameSite=Lax; Path=/season1`, 30 days (`rules.ts` `viewTokenCookie`, `welcome/route.ts:205`); the value is 32 random bytes and only its sha256 is stored (unique index). `s1_ref`: `<code>.<HMAC-SHA256 base64url>`, `HttpOnly; Secure; SameSite=Lax; Path=/`, 14 days, verified with a length check plus `timingSafeEqual`; unsigned or tampered values are ignored. `ekuzo_s1_joined` is JS-readable by spec.
- **Timing-safe comparisons.** The Stripe return client secret is compared with `safeEqual` (`timingSafeEqual`) after retrieving the PI server side (`fulfil.ts:360`); the ref cookie HMAC uses `timingSafeEqual`; the view token is looked up by hash.
- **Season 01 webhook auth.** `S1_STRIPE_WEBHOOK_SECRET` missing returns 500; `constructEvent` runs on the raw `req.text()` body; a bad or missing signature returns 400 with no detail. Events from the other Stripe mode are skipped with nothing written. Refund and dispute events re-read the charge or PI from Stripe before trusting `metadata.product`. Duplicate events are done only once `processed_at` is set; failures return 500 so Stripe retries.
- **Legacy webhook guard.** `shouldSkipLegacy` skips `product=season1`, unknown products and PIs without `parent_email`; the legacy route handles only `payment_intent.succeeded`, so Season 01 refunds and disputes never reach it. Covered by `legacyGuard.test.ts`.
- **Open redirects.** `/season1/crew`, `/season1/early-access/*` 301 to fixed paths on `new URL(request.url).origin` with the query dropped; `/karlin` 307s to a fixed path; Stripe `return_url` is `window.location.origin + '/season1/join/welcome'`; the join page signup link carries only a whitelisted `src`. No user-controlled redirect target exists.
- **SSRF.** Outbound fetches go to fixed hosts (`graph.facebook.com` with the pixel id from env, Klaviyo, Discord webhook URLs from env). The recorded origin is regex-validated and used only to build share-link strings, never fetched.
- **Rate limiting and IP source.** Client IP comes only from `x-nf-client-connection-ip` (commit, crew, signup). `x-forwarded-for` is stored separately as `consent_xff` (RT20) and never used for limits. Commit limiters fail closed (503); naming limiters fail to nameless. IPv6 is bucketed at /64 (see M1 for the commit case).
- **Error responses.** Commit returns short codes (`invalid`, `rate_limited`, `try_again`, `server`); the webhook returns `bad_signature` / `retry`; no stack traces or messages. Exceptions noted in M2.
- **Logs.** `s1 step=` lines carry step, order public id, ok and a sanitized short error code (`[A-Za-z0-9_.:-]`, 60 chars); `errCode` never logs messages. No email, name, IP or phone in any `logStep` call. Ops scripts mask emails (`a***@domain`) and print a short error code on unexpected failures. The only other `console` call is L9.
- **Minors' data flows.** Season 01 pages are served by route handlers outside `app/layout.tsx`: no Meta pixel (`fbq` absent from all five templates). GA `page_location` is origin plus path (`/crew/` without the code); the `purchase` event carries order public id, value, kid count and a has-code flag only; `history.replaceState` strips query strings before GA loads; `referrer-policy` is `origin` / `strict-origin`. Meta CAPI Purchase carries hashed email, hashed family id, consent IP and UA, fbp/fbc, value and `num_items`: no kid data, no phone; the access token travels in the body; test mode forces a test event code. Kid names never appear in URLs (codes only; legacy `?kid=` links 301 with the query dropped). Klaviyo (approved product email) gets kid first names, ages and the parent phone; test-mode sends are restricted by `testEmailAllowed`. Discord: no email, phone, address or card data, `allowed_mentions: { parse: [] }`, digit runs and markup stripped (field scope: L6).
- **Mode switch.** `resolveMode` fails closed to `off`: live needs `sk_live_`, `pk_live_`, a non-test `DATABASE_URL`, the webhook secret, deploy context `production` (inlined at build from Netlify `CONTEXT`) and a raw Host of `ekuzo.gg`/`www.ekuzo.gg`; test needs `sk_test_` plus the test DB. Commit checks mode first and calls `assertKeyMatchesMode` before creating the PI. `getSql` refuses a non-test database outside the production deploy context. Covered by `mode.test.ts`. (Substring caveat: L5.)
- **Scripts' `--live` refusal.** `initEnv` (`s1-ops-lib.mjs:82-109`): without `--live`, refuses a non-test DB and a live Stripe key; with `--live`, refuses the test DB and a test key; dry-run is the default and `--apply` is required to write (refund, attach-code, code, sweep verified). `s1-migrate.mjs` refuses a non-test host without `--live`. `s1-outbox.mjs` has no `--live` path and cannot reach production (the `getSql` guard refuses outside the production context). `s1:refund` uses a deterministic Stripe idempotency key.
- **Dependency added.** `@neondatabase/serverless` 1.2.0 (MIT, no transitive dependencies in the lockfile delta, integrity hash pinned, no audit advisories). `npm audit --omit=dev` summary: critical 1 (`next`), high 4 (`nanoid`, `postcss`, `sharp`, `source-map-js`), moderate 1 (`baseline-browser-mapping`); none introduced by this branch (H1).
- **Money-path integrity (security-relevant).** The server prices every order (`quote`) and rejects a client mismatch; fulfil claims only when PI amount, currency, `metadata.order_id` and livemode all match the order (else `pi_mismatch` flag); 3 card failures cancel the PI and flag `card_testing_suspect`; partial refunds attribute only by `s1_kid_id` metadata scoped to the order's items.
