## Verdicts

- **N2 PASS.** Ad-landing: the browser request body is identical; the only difference in the Klaviyo event and profile bodies is the added `attribution_from: "url"` (event property). The subscription call is identical.
- **N3 PASS.** The CAPI Lead body (event_name, event_id handling, content_name, user_data keys, event_source_url, fbc rebuilt from fbclid) and the browser fbq calls (set autoConfig, init, PageView, Lead with content_name and eventID) are identical on both surfaces. The popup's only browser-side change is in the /api/season-one body: two empty keys (utm_id, site) and `attributionFrom`, per F5; Meta data does not read them.
- **N5 PASS.** The games step is byte-identical after normalization: `{"kid_games":"Fortnite"}` (no attribution_from, no attribution). The popup games chip behaves the same.

Note on scope: for the popup, the added keys appear on the main sign-up request only (the f5 contract), never on the games or age step requests (RT-11 in adversarial.md also shows the route ignores them on the games step).
